# Заметки по ходу

## 2026-09-21

- Транспорт выбран stdio: так MCP-серверы запускают настольные клиенты,
  и кода меньше всего. Streamable HTTP SDK тоже умеет, но проверять
  пришлось бы порт и сессии, а задача — соединение и список инструментов.
- Инструменты объявляются через `mcp.AddTool[In, Out]`: схема аргументов
  выводится из полей структуры и тегов `json`/`jsonschema`, схема
  результата — из типа результата. Ручных JSON Schema в коде нет.
- `Server.Tools()` в SDK нет — имена инструментов пришлось запоминать при
  регистрации, ради `server_info`. Отсюда свободная функция `addTool`:
  методы в Go не бывают обобщёнными.
- Счётчик вызовов повесил на `AddReceivingMiddleware`: то же место
  пишет журнал в stderr. В stdout писать нельзя — там протокол.
- Проверка аргументов по схеме происходит **до** обработчика, но отказ
  приезжает не ошибкой протокола, а обычным результатом с `IsError`:
  `validating /properties/limit: type: двадцать has type "string", want
  "integer"`. Ошибкой протокола становится только неизвестный инструмент.
- `jsonschema-go` даёт необязательным срезам и указателям тип
  `["array","null"]`. В выводе клиента `null` убираю: то же самое говорит
  отсутствие пометки «обязательный».
- Порядок свойств в схеме — алфавитный, не по объявлению структуры.
  Клиент сортирует сам: обязательные сначала.
- Выравнивание колонок в выводе считаю по рунам. `len()` по байтам на
  кириллице разъезжается ровно вдвое.
- Тесты соединяют клиента и сервер `mcp.NewInMemoryTransports()` — живое
  MCP-соединение без процессов и труб. Википедия и GBIF подменяются
  `httptest`.
- Отладчик VS Code запускает программу из каталога её пакета, а не из
  корня модуля, и `go run ./cmd/animals-mcp` оттуда не резолвится:
  `stat …/cmd/mcp-list/cmd/animals-mcp: directory not found`, а клиент
  видит только обрыв соединения. Чинится с двух сторон: `cwd` в
  `launch.json` и поиск корня репозитория самим клиентом вверх по дереву.
- `go test -race` требует mingw-w64 в PATH: системный gcc из msys2 —
  cygwin-сборка, падает на `stddef.h`.
- SQLite взят на `modernc.org/sqlite` — SQLite, переписанный на Go.
  Компилятор C не нужен, а значит `go test -race` и сборка на чистой
  машине не упираются в mingw.
- `lower()` и `LIKE` в SQLite приводят регистр только у латиницы:
  «Тайга» и «тайга» для базы разные слова. Отсюда колонки `*_norm` —
  нормализует `strings.ToLower`, который знает Unicode.
- Списки (среда обитания, регионы, пища) — отдельные таблицы: по ним
  идёт поиск. Джойнить все три разом нельзя, строки размножились бы друг
  на друга; карточки и списки читаются отдельными запросами.
- `db.SetMaxOpenConns(1)`: SQLite — файл, пишущее соединение всё равно
  одно, а `file::memory:` без общего кэша дал бы каждому соединению пула
  свою пустую базу.
- Начальные данные подставляются только в пустую базу. Иначе удалённое
  через `delete_animal` животное воскресало бы при каждом запуске.
- `go run` собирает бинарник во временный каталог, поэтому база «рядом с
  исполняемым файлом» оказалась бы там же и исчезла. При запуске из кэша
  сборки кладём её в рабочий каталог.
- Ручной ввод: JSON правилен, но неудобен. Пары `ключ=значение` с
  запятой для списка и точкой для вложенного объекта набираются вдвое
  быстрее, а тип значения угадывается — сервер всё равно проверит его
  по схеме и ответит словами.
- Покрытие пакета `sources` показывается нулевым: его код исполняют
  тесты соседнего пакета, для честной цифры нужен `-coverpkg=./...`.
