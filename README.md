# MCP-сервер справочника по животным и минимальный клиент (Go)

Два исполняемых файла и протокол между ними.

**`animals-mcp`** — MCP-сервер со справочником по животным: одиннадцать
инструментов, пять из них работают по вшитому локальному справочнику,
пять ходят в русскую Википедию и в таксономическую базу GBIF, один
рассказывает о самом сервере. Ключей не нужно ни одному.

**`mcp-list`** — минимальный MCP-клиент: устанавливает соединение,
проходит рукопожатие `initialize`, запрашивает `tools/list` и печатает,
что сервер о себе рассказал, — имя, версию, версию протокола, свои
возможности и каждый инструмент со схемой аргументов. Затем делает
несколько проверочных вызовов: список инструментов — это обещание
сервера, а вызов — его исполнение.

Клиент не знает ничего про животных. Ему можно передать любой другой
MCP-сервер, запускаемый по stdio, и он так же покажет его инструменты.

## Что нужно

- Go 1.25 или новее;
- доступ в интернет к `ru.wikipedia.org` и `api.gbif.org` — только для
  пяти онлайн-инструментов; локальные работают и без сети.

## Запуск

```bash
git clone https://github.com/AlexS8332/AITrenning_Task16.git
cd AITrenning_Task16
go run ./cmd/mcp-list
```

### Флаги клиента

```bash
go run ./cmd/mcp-list -no-demo          # только список инструментов
go run ./cmd/mcp-list -schemas          # плюс полные JSON Schema аргументов
go run ./cmd/mcp-list -full             # результаты вызовов целиком, без обрезки
go run ./cmd/mcp-list -call random_animal
go run ./cmd/mcp-list -call get_animal -args '{"animal":"Обыкновенная рысь"}'
go run ./cmd/mcp-list -call match_taxon -args '{"scientific_name":"Lynx lynx"}'
go run ./cmd/mcp-list -- go run ./cmd/animals-mcp -v   # с журналом сервера в stderr
```

После `--` идёт команда запуска любого другого MCP-сервера — клиенту
всё равно, чей список инструментов показывать.

### Сервер отдельно

```bash
go build -o animals-mcp ./cmd/animals-mcp
```

Запущенный вручную сервер молча ждёт JSON-RPC на стандартном вводе —
это нормально, говорить с ним должен клиент. Флаг `-v` включает журнал
вызовов в stderr (stdout занят протоколом).

Чтобы подключить сервер к любому MCP-клиенту (Claude Desktop, Claude
Code, IDE), укажите в его настройках запуск собранного бинарника:

```json
{
  "mcpServers": {
    "animals": {
      "command": "/полный/путь/animals-mcp"
    }
  }
}
```

## Инструменты

По локальному справочнику — 20 видов, данные вшиты в бинарник, сеть не
нужна:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `list_animals` | `class`, `habitat`, `limit`, `offset` | список с фильтрами и постраничной выдачей |
| `get_animal` | `animal`\* | карточка по идентификатору, русскому или латинскому названию |
| `search_animals` | `query`, `diet`, `habitat`, `min_weight_kg`, `max_weight_kg` | поиск, условия складываются |
| `compare_animals` | `animals`\*, `fields` | таблица сравнения двух-четырёх животных |
| `random_animal` | — | случайная карточка |

По внешним источникам, ключей не требуют:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `search_wikipedia` | `query`\*, `limit` | поиск статей в русской Википедии |
| `read_wikipedia` | `title`\*, `section` | без раздела — вступление и оглавление, с разделом — его текст |
| `match_taxon` | `scientific_name`\* | сверка латинского названия с GBIF |
| `taxon_tree` | `usage_key` или `scientific_name` | дерево классификации от царства до таксона |
| `vernacular_names` | `usage_key`\*, `language` | народные названия по данным GBIF |

И один служебный:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `server_info` | — | версия, список инструментов, сводка по справочнику, источники, счётчик вызовов за сессию |

\* — обязательный аргумент.

Отсутствие сведений — обычный результат, а не ошибка: `get_animal` на
неизвестное животное отвечает `found=false` и показывает похожие записи,
`match_taxon` на выдуманную латынь — `found=false` с пояснением, почему
похожее совпадение не считается совпадением.

## Как устроено

```
cmd/animals-mcp      сервер: собирает инструменты и слушает stdio
cmd/mcp-list         клиент: соединение, tools/list, разбор схем, вызовы
internal/catalog     локальный справочник: данные в animals.json, фильтры, сравнение
internal/sources     Википедия и GBIF: запросы, разбор, кэш ответов в памяти
internal/mcpserver   объявление инструментов: схемы аргументов и обработчики
```

Инструменты объявляются типами: у каждого свои структуры аргументов и
результата, а JSON Schema для `tools/list` выводится из полей и тегов
`json`/`jsonschema`. Поэтому описание инструмента, его схема и код
обработчика не могут разойтись — они одно и то же объявление.

Транспорт — stdio: клиент запускает сервер дочерним процессом и говорит
с ним через его стандартный ввод-вывод. Так же MCP-серверы запускают
настольные клиенты.

Протокол: [Model Context Protocol](https://modelcontextprotocol.io),
реализация — [официальный Go SDK](https://github.com/modelcontextprotocol/go-sdk).

## Тесты

```bash
go test ./...
go test -race ./...
go test -coverpkg=./... ./...
```

Тесты поднимают настоящее MCP-соединение, но без процессов и труб:
клиент и сервер соединяются транспортом в памяти. Сеть не нужна —
Википедия и GBIF подменяются локальными HTTP-серверами. Проверяются
рукопожатие, состав и схемы инструментов, все вызовы, поведение при
неверных аргументах и то, что ошибка инструмента приезжает результатом,
а не обрывом соединения.
