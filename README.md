# MCP-сервер справочника по животным и минимальный клиент (Go)

Два исполняемых файла и протокол между ними.

**`animals-mcp`** — MCP-сервер со справочником по животным: четырнадцать
инструментов. Восемь работают со справочником в базе SQLite — пять
читают, три меняют; пять ходят в русскую Википедию и в таксономическую
базу GBIF; один рассказывает о самом сервере. Ключей не нужно ни одному.

**`mcp-list`** — минимальный MCP-клиент: устанавливает соединение,
проходит рукопожатие `initialize`, запрашивает `tools/list` и печатает,
что сервер о себе рассказал, — имя, версию, версию протокола, свои
возможности и каждый инструмент со схемой аргументов. Затем делает
несколько проверочных вызовов: список инструментов — это обещание
сервера, а вызов — его исполнение.

Клиент не знает ничего про животных. Ему можно передать любой другой
MCP-сервер, запускаемый по stdio, и он так же покажет его инструменты.
С флагом `-i` он переходит в ручной режим, где команды и вызовы
набирает человек.

## Что нужно

- Go 1.25 или новее;
- доступ в интернет к `ru.wikipedia.org` и `api.gbif.org` — только для
  пяти онлайн-инструментов; работа со справочником сети не требует.

Базу данных ставить не нужно: SQLite встроен в бинарник (драйвер на
чистом Go, без cgo), файл создаётся при первом запуске.

## Запуск

```bash

cd AITrenning_Task16
```

### Ручной режим

```bash
go run ./cmd/mcp-list -i
```

Соединение остаётся открытым, а команды набирает человек:

```
> tools animal
  add_animal        Добавить животное
  compare_animals   Сравнение животных
  delete_animal     Удалить животное
  get_animal        Карточка животного
  list_animals      Список животных
  random_animal     Случайное животное
  search_animals    Поиск по справочнику
  update_animal     Изменить животное

> get_animal animal=рысь
> list_animals class=птицы limit=3
> add_animal id=platypus name="Утконос" scientific_name="Ornithorhynchus anatinus" class=млекопитающие weight_kg.min=0.7 weight_kg.max=2.4
> delete_animal animal=platypus
```

| Команда | Что делает |
|---|---|
| `tools [фильтр]` | список инструментов |
| `schema <инструмент>` | аргументы инструмента; `schema <инструмент> json` — схема целиком |
| `call <инструмент> [аргументы]` | вызов; слово `call` можно опустить |
| `info` | сведения о сервере и `server_info` |
| `full on\|off` | печатать результаты целиком или обрезанными |
| `help`, `quit` | справка и выход (выход — ещё и Ctrl+D) |

Флаг `-timeout` (по умолчанию 2 минуты) в ручном режиме ограничивает
каждый вызов по отдельности, а не весь сеанс: думать между командами
можно сколько угодно. Ctrl+C прерывает затянувшийся вызов, Ctrl+D
завершает сеанс.

Аргументы пишутся либо JSON-объектом, либо парами `ключ=значение`:
запятая делает список (`animals=lynx,amur-tiger`), точка — вложенный
объект (`weight_kg.min=0.7`), кавычки удерживают пробелы
(`name="Малая панда"`). Тип значения угадывается: число, `true`/`false`,
иначе строка. Схему помнить не нужно — `schema <инструмент>` показывает
имена и типы, а сервер всё равно проверит аргументы и скажет, что не так.

### Флаги клиента

```bash
go run ./cmd/mcp-list -no-demo          # только список инструментов
go run ./cmd/mcp-list -schemas          # плюс полные JSON Schema аргументов
go run ./cmd/mcp-list -i                # ручной режим
go run ./cmd/mcp-list -full             # результаты вызовов целиком, без обрезки
go run ./cmd/mcp-list -call random_animal
go run ./cmd/mcp-list -call get_animal -args 'animal=Обыкновенная рысь'
go run ./cmd/mcp-list -call match_taxon -args '{"scientific_name":"Lynx lynx"}'
go run ./cmd/mcp-list -- go run ./cmd/animals-mcp -v   # с журналом сервера в stderr
```

После `--` идёт команда запуска любого другого MCP-сервера — клиенту
всё равно, чей список инструментов показывать. Ручной режим работает и с
ним: `mcp-list -i -- npx @modelcontextprotocol/server-everything`.

### Сервер отдельно

```bash
go build -o animals-mcp ./cmd/animals-mcp
```

Запущенный вручную сервер молча ждёт JSON-RPC на стандартном вводе —
это нормально, говорить с ним должен клиент. Флаг `-v` включает журнал
вызовов в stderr (stdout занят протоколом).

Чтобы подключить сервер к любому MCP-клиенту (Claude Desktop, Claude
Code, IDE), укажите в его настройках запуск собранного бинарника:

```json
{
  "mcpServers": {
    "animals": {
      "command": "/полный/путь/animals-mcp"
    }
  }
}
```

## Инструменты

Чтение справочника — 20 видов в базе SQLite, сеть не нужна:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `list_animals` | `class`, `habitat`, `limit`, `offset` | список с фильтрами и постраничной выдачей |
| `get_animal` | `animal`\* | карточка по идентификатору, русскому или латинскому названию |
| `search_animals` | `query`, `diet`, `habitat`, `min_weight_kg`, `max_weight_kg` | поиск, условия складываются |
| `compare_animals` | `animals`\*, `fields` | таблица сравнения двух-четырёх животных |
| `random_animal` | — | случайная карточка |

Изменение справочника. У этих инструментов `readOnlyHint=false`, у
удаления ещё и `destructiveHint=true` — по этим пометкам клиент решает,
спросить ли разрешения у человека перед вызовом:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `add_animal` | `id`\*, `name`\*, `scientific_name`\*, `class`\* и остальные поля карточки | добавляет запись; занятый идентификатор — отказ, а не замена |
| `update_animal` | `animal`\* и любые изменяемые поля | меняет переданные поля, списки заменяет целиком |
| `delete_animal` | `animal`\* | удаляет запись и возвращает её напоследок |

По внешним источникам, ключей не требуют:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `search_wikipedia` | `query`\*, `limit` | поиск статей в русской Википедии |
| `read_wikipedia` | `title`\*, `section` | без раздела — вступление и оглавление, с разделом — его текст |
| `match_taxon` | `scientific_name`\* | сверка латинского названия с GBIF |
| `taxon_tree` | `usage_key` или `scientific_name` | дерево классификации от царства до таксона |
| `vernacular_names` | `usage_key`\*, `language` | народные названия по данным GBIF |

И один служебный:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `server_info` | — | версия, список инструментов, путь к базе и сводка по ней, источники, счётчик вызовов за сессию |

\* — обязательный аргумент.

Отсутствие сведений — обычный результат, а не ошибка: `get_animal` на
неизвестное животное отвечает `found=false` и показывает похожие записи,
`match_taxon` на выдуманную латынь — `found=false` с пояснением, почему
похожее совпадение не считается совпадением.

## База данных

Справочник живёт в SQLite. Файл создаётся при первом запуске сервера и
наполняется начальными данными из `internal/catalog/animals.json`, а
дальше живёт своей жизнью: добавленное через `add_animal` переживает
перезапуск, а удалённое не возвращается — данные подставляются только в
пустую базу.

Путь к файлу задаётся флагом `-db`. По умолчанию это `animals.db` рядом
с исполняемым файлом (при `go run` — в рабочем каталоге, потому что сам
бинарник лежит во временном каталоге сборки). Особое значение
`:memory:` держит справочник только в памяти процесса — удобно, когда
нужна заведомо чистая база:

```bash
go build -o animals-mcp ./cmd/animals-mcp
./animals-mcp -db /var/lib/animals/animals.db
go run ./cmd/mcp-list -- go run ./cmd/animals-mcp -db :memory:
```

Драйвер — `modernc.org/sqlite`, SQLite, переписанный на Go: компилятор C
не нужен ни для сборки, ни для тестов. Схема — в
`internal/catalog/schema.sql`: карточки в `animals`, списки (среда
обитания, регионы, пища) отдельными таблицами, потому что по ним идёт
поиск. Рядом с каждым текстовым полем лежит колонка `*_norm` — то же
значение в нижнем регистре: `lower()` и `LIKE` в SQLite приводят регистр
только у латиницы, поэтому кириллицу нормализует Go.

Удалить файл базы не страшно — сервер создаст её заново из начальных
данных. В git она не попадает.

## Как устроено

```
cmd/animals-mcp      сервер: собирает инструменты и слушает stdio
cmd/mcp-list         клиент: соединение, tools/list, разбор схем, вызовы, ручной режим
internal/catalog     справочник в SQLite: схема, начальные данные, запросы, запись
internal/sources     Википедия и GBIF: запросы, разбор, кэш ответов в памяти
internal/mcpserver   объявление инструментов: схемы аргументов и обработчики
```

Инструменты объявляются типами: у каждого свои структуры аргументов и
результата, а JSON Schema для `tools/list` выводится из полей и тегов
`json`/`jsonschema`. Поэтому описание инструмента, его схема и код
обработчика не могут разойтись — они одно и то же объявление.

Транспорт — stdio: клиент запускает сервер дочерним процессом и говорит
с ним через его стандартный ввод-вывод. Так же MCP-серверы запускают
настольные клиенты.

Протокол: [Model Context Protocol](https://modelcontextprotocol.io),
реализация — [официальный Go SDK](https://github.com/modelcontextprotocol/go-sdk).

## Тесты

```bash
go test ./...
go test -race ./...
go test -coverpkg=./... ./...
```

Тесты поднимают настоящее MCP-соединение, но без процессов и труб:
клиент и сервер соединяются транспортом в памяти. Сеть не нужна —
Википедия и GBIF подменяются локальными HTTP-серверами, а база у каждого
теста своя, во временном файле. Проверяются рукопожатие, состав, схемы и
аннотации инструментов, все вызовы, запись в базу и её сохранность после
переоткрытия, разбор аргументов ручного режима, поведение при неверных
аргументах и то, что ошибка инструмента приезжает результатом, а не
обрывом соединения.
